Text widths from the font file, checked against your browser

typeset reads the advance of each glyph and the kerning from the font tables. It does not draw the text. This page loads a real font, measures text with the tables and with the canvas of your browser, and shows the difference.

Justified lines hyphens

Total fit breaks the text with the hyphen patterns of the language. The spaces of each line stretch or shrink to the edge. Greedy with no hyphens is next to it.

Line width

The number at the end of each line is its adjustment ratio. At 1, the spaces stretch by a half of a space. At -1, they shrink by a third of a space. A ratio out of this range is red. The worst ratio is the measure of the justified edge.

Font stacks

Each row is a CSS font list. The model gives each character cluster to the first font that has it, as Chromium does. Each cell shows the worst error over 6 sizes. The limit is 1.28/64 px.

A covered row has only texts with a glyph for each character. An uncovered row has the texts as the corpus draws them. Chromium draws a character that no font of the list has with a system font, so its width is not defined. That row shows the error outside such runs.

Select a cell to see the worst error at each size.

Sequences: canvas against the model

Each row is a group of hard texts: bidi controls, emoji sequences and kerning across hidden characters. The canvas and the model measure each text at 96 px. Each cell shows the worst distance in px.

The model does not shape emoji sequences, and it names that risk for each such text. The group of mixed directions has a gate: each text is at most 0.5 px from the model.

Select a cell to see its worst text and the texts more than 1/64 px off.

Line breaks of the font stacks

Chromium lays out each text in a box at 10, 16 and 48 px. The box is 8 or 20 times the size. Each cell counts the texts with the same lines as the model.

A cell passes when 97 of each 100 texts have the same lines. A known gap fails for a known cause, and it names the item that closes it. A known gap is not a pass.

Select a cell to see the causes and the item that closes a gap.

How it works

  • The model reads hmtx, HVAR, GSUB and GPOS of the font file. It adds the advances and the kerning of each canvas word.
  • The reference is measureText of a canvas, with the same file loaded as a FontFace.
  • An engine model is a row of rules for one text engine: the rounding of the variable-font deltas, the metrics of composite glyphs, the rounding of each advance and the precision of the sum.
  • On macOS and Windows, Blink adds the widths of the words in single precision. The CoreText and DirectWrite models do the same.
  • Arabic needs joining forms. The model applies them by the joining type of each letter, as HarfBuzz does.
  • Devanagari needs the Indic shaper of HarfBuzz. The model finds the syllables, reorders the reph and the pre-base matra, and applies the features in their stages.
  • The fonts come from google/fonts at a pinned commit. Read docs/FONTS.md for the measurements.
