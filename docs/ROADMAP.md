# Roadmap

Each item has a prediction before its code: the claims, how each claim is measured, its base and its noise.

| Id | Item | Priority | Status | Depends on |
|---|---|---|---|---|
| T1 | Font tables: read the glyph advances and the kerning pairs from a font file (TrueType, OpenType, WOFF2); a font epoch; a bench against canvas `measureText` on a corpus of fonts | P1 | done | T9 |
| T1b | Variable fonts (`fvar`, `avar`, `HVAR`) at the weight of the CSS; a rounding mode to whole px; the comparison on Linux at the device scale 2, on macOS and on Windows, with a bound for each platform | P1 | done | T1 |
| T1c | The errors that remain after T1b. The GSUB pass (typeset#25), the instance advances (typeset#27), the table of engine rules (typeset#29) and the words of a canvas (typeset#31) close them. Each script except Arabic and Devanagari is now at most 0.0014 px on each platform | P1 | done | T1b |
| T1d | Arabic joining forms and an Indic shaper in the model, so that the widths of Arabic and Devanagari text are correct. Arabic is done: 240 of 240 lines within 0.01 px on the four arms (typeset#34). On macOS and Windows, the sum `float32` of the canvas gives the paragraphs and the pages within 0.01 px. The Indic shaper gives 240 of 240 Devanagari records within 0.01 px in each length class on the four arms (typeset#44) | P1 | done | T1c |
| T1e | The Latin Extended pages: only 642 (Linux) or 582 (macOS, Windows) of 720 pages are within 0.01 px, and the worst is 5.2 px. The cause is the Unicode normalization of HarfBuzz, which only the Indic shaper of the model had. The fix is in progress | P2 | in progress | T1d |
| T1f | A Devanagari vowel sign after an independent vowel (U+0906 U+0948): the model and Chrome put a dotted circle, HarfBuzz 15.0.0 does not. The Unicode and OpenType rules for broken clusters decide it, with the HarfBuzz change log as evidence. The model changes only after the decision | P2 | later | T1d, T4 |
| T2 | The `Text` rope of `@mark1russell7/typeset/text`: a persistent balanced tree with the width and the length of each part. Concatenation, slice and edits measure only the changed leaves and a window of about one word at each seam. The width is equal to the width of the flat string for each width function that obeys the separator law, and the CI tests it with the real fonts: 12 scripts and Source Sans 3, 200 edit sequences each, on the four arms (typeset#47) | P1 | done | T1 |
| T2b | The `Text` rope on the `SummaryTree` of `@procedures/collections`, pinned to `client#e1ce6f4d` until the npm release. The local tree goes away. A committed record of the width calls of each seed is the limit, at most 32 for each insert | P1 | later | T2, T8 |
| T3 | Line breakers as strategies: greedy, Knuth-Plass total fit and balanced, with the measures line count, raggedness and time, on the corpus and in the CI bench. `@mark1russell7/typeset` 0.1.0 has them in the subpath `./breaking`, see [BREAKING.md](BREAKING.md). `layoutText` of `@mark1russell7/layout-contract` 0.3.2 uses them, with the same output as 0.2.21 and the option `breaker` (layout-contract#148). The rope (T2) makes it incremental | P1 | done | T1c |
| T4 | Error bounds: the error of the fast path against a shaper (HarfBuzz) for each script and font, in 1/64 px; size scaling and hinting per font | P1 | done | T1 |
| T4b | Each engine row against its real engine: the same texts in Chromium on the macOS (CoreText), Windows (DirectWrite) and Ubuntu (FreeType) runners of CI. The canvas widths are the reference of each row. Then a reference checks the read effect of T4 | P2 | later | T4 |
| T5 | The bound fast path: `widthBound` of `./fonts` gives a limit of the width for a declared set of characters, with no measurement | P2 | done | T1 |
